# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A single-page marketing site for **JEO Maps** (geographic intelligence in WordPress). It is a faithful reproduction of the approved **Figma v3 redesign** — the source of truth for layout, spacing, and the canonical **PT-BR copy** (English is a translation kept in sync in the dictionaries). When changing text or layout, match the design rather than inventing content.

The approved layout is the frame `jeo-maps-landing-redesign` (**node `133:1531`**, page "entrega 15/9/26", 1920×8448) in the Figma file **"JEO MAPS entregas"** (`uPSQi0186RdpE4rg2aeq7q`), rendered to `figma-ref/desktop-v3.png`. The token inventory lives in `figma-ref/redesign-v3-tokens.md`. The previous **V2** design (JEO BRAINS, `desktop-v2.png`) and all of its components, assets and Tailwind tokens were **removed** in the final cleanup — don't resurrect them from git history without a fresh decision.

The app lives in `www/`. All commands below run from there.

## Commands

```bash
cd www
npm install
npm run dev      # Vite dev server → http://localhost:5173/novo (base '/novo', see vite.config.js)
npm run build    # production build → dist/
npm run preview  # serve the production build
```

There is **no test runner and no linter configured** — don't reference `npm test`/`npm run lint`. Verify changes by building and visually checking in the browser (desktop 1920 + mobile 390, PT-BR + EN).

## Stack

React 18 + Vite 5 (with `base: '/novo'` for homologation behind a tunnel — ngrok hosts are pre-allowed in `vite.config.js`), Tailwind CSS 3 (classic config + PostCSS), Framer Motion (animation), lottie-web (official hero Lottie player; SVG-only ESM build), lucide-react (icons), and a **dependency-free i18n** built on React context (see below).

The whole page uses **Open Sans** for both `display` and `sans` — loaded via Google Fonts in `index.html` as the variable font **with the width axis** (`Open+Sans:wdth,wght@75..100,300..800`). Most v3 headings are **Open Sans Condensed**: apply the `.font-condensed` utility (defined in `index.css` as `font-stretch: 75%`, which maps to the wdth axis) together with `uppercase` and `font-bold`.

## Architecture

- **`src/App.jsx`** composes the page in fixed Figma order — `Header`, `Hero`, `ResourceSlider` (`#recursos`), `FeaturesShowcase` (`#inteligencia-artificial`), `HowItWorks`, `LiveDemo` (`#experimente`), `WorkshopsV3` (`#oficinas`), `FooterV3` — plus the global UI: a mint scroll-progress bar (`useScroll`/`useSpring`) and the `ConsentBanner`. To reorder or add a section, edit the JSX here.
- **`src/i18n/`** is the i18n system, written from scratch (no dependency — an explicit round decision): `index.jsx` holds the context/provider/hook (`useI18n` → `{ lang, setLang, t }`), the `LANGUAGES` list (`pt-BR` default, `en`) and persistence (`localStorage['jeo-lang']`, plus `document.documentElement.lang` sync); `pt-BR.js` / `en.js` are flat dictionaries namespaced per section (`nav.*`, `hero.*`, `slider.*`, `showcase.*`, `hiw.*`, `demo.*`, `workshops.*`, `footer.*`, `consent.*`). **All user-facing copy lives in the dictionaries** — adding a language = adding one dictionary file + one `LANGUAGES` entry.
- **`src/components/Header.jsx`** is a sticky top bar (`sticky top-0 z-40`, 118px on desktop) with the JEO Maps wordmark, 4 anchor links (scroll-spy active state + underline), the "Instalar Plugin" CTA, a **PT-BR/EN language switcher** (dropdown listbox; also inside the mobile menu) and the mobile hamburger menu.
- **`src/links.js`** centralizes external destinations — `DOWNLOAD_URL` (wordpress.org plugin page), `DOCS_URL` (jeowp.org), `GITHUB_URL` (the repo). All external links open in a new tab (`target="_blank" rel="noopener noreferrer"`).
- **`src/components/ConsentBanner.jsx`** (rendered last in `App.jsx`) is a bottom-left cookie/terms notice shown only on the first visit; "Aceitar" writes `localStorage['jeo-consent-v1'] = 'accepted'`. Fully v3-styled and translated (`consent.*`). On desktop it sits at `sm:bottom-24` so it clears the 64px footer bottom bar (where the terms trigger lives) instead of covering it.
- **`src/components/FooterV3.jsx`** carries the **terms-of-use modal** (button in the bottom bar). The trigger is translated (`footer.termsLead`/`termsLink`); the **modal body is placeholder PT-BR by design** (pending legal content — registered in issue #669).
- **`src/components/ui/Reveal.jsx`** is the shared scroll-in animation wrapper used by nearly every section — prefer wrapping new content in `<Reveal>` for consistent, reduced-motion-aware entrances.
- **`src/components/ui/Lottie.jsx`** is the lottie-web wrapper (SVG renderer) used by the Hero, the ResourceSlider tabs and the FeaturesShowcase row media: `animationData`, `loop`, `autoplay`, `title` (→ `role="img"` + `aria-label`; no title → `aria-hidden`), plus two additive props (2026-09-17): `approachMargin` (one-shot IntersectionObserver with that rootMargin — the player + JSON chunks are only fetched when the box approaches the viewport, keeping below-the-fold media out of the initial page load; still fetched under reduced motion because the settled frame needs the data) and `replayOnReenter` (every fresh entry into the viewport restarts from frame 0 — narrative scroll-navigation; in-view play-once + hold otherwise). It pauses outside the viewport (`IntersectionObserver`) and when `document.hidden`, resumes on return, disposes cleanly on unmount, and under `prefers-reduced-motion` never animates — it jumps to the final settled frame (`goToAndStop(totalFrames-1)`).
- **One component per section**; section content (tabs, features, steps) is data at the top of each file or in the i18n dictionaries, mapped into markup.

### Conventions

1. **Design tokens live in `www/tailwind.config.js`** — the `v3-*` palette (`v3-navy`, `v3-navy-hero`, `v3-light`, `v3-mint`, `v3-green`, `v3-green-dark`, `v3-accent`, `v3-teal`, `v3-gray` + neutral `muted`/`muted-2`), `maxWidth['v3-content']` (1600px) and `boxShadow.card`. Reusable component classes (`.section-shell-v3`, `.btn-v3-primary`, `.btn-v3-ghost`, `.btn-v3-secondary`, `.eyebrow-v3`) and base styles live in `@layer` blocks in `www/src/index.css`, plus the `.font-condensed` utility. Use these instead of hardcoding hex values or repeating button/container markup. `v3-navy-footer` is a **reserved** token (see footer decision below).
2. **`prefers-reduced-motion` is sacred.** `index.css` globally neutralizes CSS animations/transitions, and every animated component guards itself with `useReducedMotion()` (videos degrade to their poster — LiveDemo — or to the static navy backdrop — Hero; parallax/float loops are skipped). Keep new motion behind the same guard.
3. **Assets in `src/assets/`**: all `v3-*` PNGs were **exported from Figma** (not redrawn) — wordmarks (navbar + footer), tab icons, feature arts, slider art, the demo print/poster. The hero illustration is the **official Lottie export** `src/assets/animations/find-location.json` (the manual layer PNGs `v3-hero-txt/pin/search/maps/sparkle-*` were deleted with the manual recreation). Reused from V2: `hacklab-logo.svg` (footer partner logo) and `print-animado.mp4` (the Live Demo video). The favicon is `public/favicon.svg` (independent of `src/`). Known gap: the six 1× crops (features 1–5, demo print, footer wordmark) still await a 2× reexport — the Figma MCP export endpoint times out (-32001); dimensions already match the Figma rects 1:1, so they render correctly, just not retina-sharp. (`v3-feature-1.png` is back in this group: restored 2026-09-17 by cropping `figma-ref/desktop-v3.png` at the Group 17 bounds after the Lottie revert below.) The former `v3-hero-bg-pattern.png` texture (1586×960, the 2× line-art export of `hero-animate`, applied full-hero at `opacity-[0.08]`) was **reverted and deleted** (2026-09-16): it read as a "ghost thumbnail" of the animation behind the copy. The official hero background is the full fill stack declared in the 15/9 Figma delivery (frame `133:1553`), wired in 2026-09-16: the **official background video** `src/assets/hero-background.mp4` — the V2 asset provided by the human (restored byte-identical, md5 `c32c7b68…`) was **re-encoded once for performance on 2026-09-16** (see "First-fold performance" below: 9.4 MB → 2.97 MB, CRF 30 + bitrate cap, `+faststart`; the untouched source lives with the human, never re-encode from `src/assets/`) — emitted by Vite as a hashed static asset outside the JS bundle, loaded async with the first-frame poster `src/assets/hero-poster.jpg`, at `opacity-80 object-cover`, under two navy `#0A1628` solids (one `mix-blend-color`, one at 90%), topped by the vertical gradient (transparent at the bottom → opaque navy at the top). Under `prefers-reduced-motion` the `<video>` is not rendered — the static navy + gradient backdrop shows, with no flash.

### Decisions worth preserving (don't regress)

These are choices made and reviewed across the redesign slices (S1–S7, issue #669). Treat changing them as a fresh proposal, not a "fix".

- **Uppercase-condensed headings carry mixed-case copy.** Dictionary strings keep natural capitalization ("Experimente o JEO na prática", "Comece do seu jeito"); the all-caps Figma look comes from `font-condensed … uppercase … font-bold` classes. Don't bake uppercase into the i18n strings — EN translations and screen readers stay sane.
- **`section-shell-v3` is the single container convention**: `max-w-v3-content` (1600px) + `px-6 sm:px-10`. Figma declares 160px side margins at 1920; the accepted compromise (S3/S4/S6, kept for consistency) is the 1600px cap with inset padding, which yields ~40px narrower content than Figma's 1600px content box. Don't mix per-section 160px margins back in.
- **The workshop form is a placeholder by human decision** (2026-09-15): native validation, submit flips to a local "Inscrições em breve" state, zero network calls. Real backend is a future task — don't wire one in silently.
- **Footer top band uses the baked `#0D192B` background** so `v3-footer-wordmark.png` (which carries that exact baked background, not transparency) blends seamlessly. The tokens doc lists `#101C2E` (`v3-navy-footer`) — that token is **reserved** as the swap-in if the wordmark is ever replaced with a transparent export. `codesinfo` is intentionally absent from the v3 footer.
- **i18n has no dependency** (React context + two dictionaries, `localStorage['jeo-lang']`). Adding react-i18next or similar is a fresh proposal, not an upgrade.
- **The `text-base` collision is resolved by removal**: the V2 palette — including the color `base` — was deleted from the Tailwind config, so `text-base` is now purely the font-size utility. If a future color token collides with a Tailwind utility name, prefix it (that's what `v3-*` is for).

### First-fold performance (2026-09-16, issue #669 slice)

Measured on production builds (`npm run build` + a cold-cache no-store static server, one virgin port per run; the dev server is not representative — unminified modules, no chunk hashing, ESM waterfalls). Median of 3 cold runs, before → after:

| metric | before | after |
|---|---|---|
| FCP | 812 ms | 480 ms |
| LCP (was the video's 1st frame, now the poster) | 2364 ms | 732 ms |
| Lottie 1st SVG render | 1871 ms | 1061 ms |
| video 1st frame | 2336 ms | 1427 ms |
| bytes downloaded during load | ~32 MB (both videos) | ~3.9 MB |

Decisions — treat changing any of these as a fresh proposal:

- **Hero video re-encode** (the big lever). The V2-original 9.4 MB MP4 had its `moov` atom at the **end** (no faststart), forcing the browser to download essentially the whole file before the first frame — and the `<video>` was the LCP element. Re-encoded from the human's untouched source: `ffmpeg -i source -vf scale=1280:720 -c:v libx264 -crf 30 -maxrate 1150k -bufsize 2300k -preset slow -an -movflags +faststart -pix_fmt yuv420p` → **2.97 MB**, PSNR vs source **32.2 dB average** (≥ 32 dB gate for the aggressive path; CRF 28 alone measured 37.2 dB but 6.2 MB). Under the hero's overlays (`opacity-80` + `mix-blend-color` navy + navy/90) the difference is invisible. Always re-encode from the human's source file, never from `src/assets/`.
- **`hero-poster.jpg`** (76 KB, frame 0, `-q:v 5`, 1280×720): paints under the overlays the moment React mounts the video, before any video byte arrives; being frame 0 the handover to playback is seamless. This is what moved LCP: the poster (a fast image) is now the LCP element instead of the video.
- **Lottie waterfall**: both async chunks (player 241 KB + `find-location.json` 274 KB) are kicked at **module-evaluation time** in `Hero.jsx` top-level (import() dedupes by module, so `Lottie.jsx`'s own effect-time calls resolve to the in-flight promises). Rejected alternatives: a hashed `<link rel="modulepreload">` in `index.html` (breaks on every rebuild — hashes change) and statically importing the JSON into the main bundle (~25 KB gzip added to the text's critical path for ~600 ms of animation onset — bad trade).
- **LiveDemo video deferred**: `preload="none"` + IntersectionObserver play/pause (600px margin). The 22.5 MB recording used to start downloading at ~1.4 s — before the hero's LCP — and trickle for ~36 s.
- **Fonts were already correct**: `display=swap` + preconnect to `fonts.googleapis.com`/`fonts.gstatic.com` (single variable woff2, 83 KB). No change needed.
- `prefers-reduced-motion` still renders no video at all (0 MP4 requests), and the Lottie shows its settled final frame — unchanged by any of the above.
